# AGENTS.md — правила для ИИ-агентов в репозитории VKataxa

## Что это
Мод-клиент VK для Android. `smali/` — декомпилированный клиент VK 5.56.1 через apktool (52 196 файлов, **чужой сгенерированный код**). `app/` — наш код (Java, 383 файла, ~28,5 тыс. строк): хуки, настройки, музыка, сеть, БД, темы. APK собирается `apktool b smali/`; Gradle компилирует только `app/` в дополнительные `classesN.dex`.

## Команды
- Компиляция мод-кода (быстро, без APK): `./gradlew :app:compileDevJavaWithJavac`
- Полная сборка APK: `./gradlew buildVTLDev` (Windows: `gradlew.bat buildVTLDev`)
- Тесты (появятся в рамках работ): `./gradlew test`
- Проверка APK: `java -jar scripts/apksigner.jar verify --print-certs build-output/VTLite.apk`

## Скорость и контекст (соблюдать обязательно)

- Сначала читай `docs/CODEMAP.md` и `docs/FACTS.md`. Не сканируй репозиторий, чтобы «понять проект».
- `grep`/`glob` — только по `app/src/main/java/ru/vtosters/**` или по конкретному пакету. Поиск по
  всему репозиторию запрещён: в нём 52 196 файлов `smali/`.
- Не читай файлы длиннее 300 строк целиком: `offset`/`limit`, 10–40 строк вокруг нужного метода.
- Не открывай `com/vtosters/lite/R.java`, `app/libs/**`, `smali/**`, `build-output/**`.
- Нужен образец кода — `docs/RECIPES.md`. Не выдумывай API: сверяй с существующим кодом или
  `javap -classpath app/libs/classes-dex2jar.jar <класс>` / jadx.
- Компиляция (быстро, минимум вывода):
  `./gradlew :app:compileDevJavaWithJavac --offline --console=plain -q`.
  Полная сборка — только если менял ресурсы/smali или перед коммитом.
- Одна задача за сессию. Если ответы «поплыли» — закончи текущую задачу, обнови `FEATURES.md` и
  начни новую сессию с ID задачи.
- Факты из `docs/FACTS.md` считаются истинными, пока не доказано обратное. Повторно их не исследуй.

## Жёсткие запреты
1. **Не редактируй `smali/`** без явного указания задачи на конкретный файл. Правка smali вслепую ломает `.registers`/типы и даёт `VerifyError` в рантайме при зелёной сборке.
   **Единственное разрешённое исключение:** текст строк в `smali/res/values*/strings.xml` (только значения строк, не `public.xml` и не ID) — и только по задаче, где это прямо указано.
2. **Не редактируй** `app/src/main/java/com/vtosters/lite/R.java` (генерируется из `smali/res/values/public.xml`), `app/libs/*.jar`, `scripts/*.jar`, `scripts/framework/`, `*.dex`, `build-output/`.
3. **Не переформатируй** файлы целиком, не сортируй импорты в чужих файлах, не меняй стиль — только минимальный дифф по задаче.
4. **Не меняй** `applicationId`, `namespace`, версии `versionCode`/`versionName`, keystore — это ломает обновления поверх установленной сборки.
5. **Не удаляй** чужие `printStackTrace` пачкой — только в рамках конкретной задачи, с заменой на логгер.
6. **Не апгрейди** AGP/Gradle/плагины без отдельной задачи.
7. **Не оставляй** в коде `TODO` без номера задачи; не добавляй зависимости без явного согласия.

## Как работать
- Сначала прочитать файл(ы), потом менять. Одна задача = один логический коммит.
- Правки — не больше 3–5 файлов за шаг. Больше — разбей на шаги.
- Каждая правка проверяется командой из списка выше. **Нельзя сообщать об успехе без вывода команды.**
- Если правка требует изменить поведение VK-классов (`com/vk/**`, `com/vtosters/**` внутри `app/`) — это переписанные классы клиента: трогать только по задаче, диффом.
- Исключения из мода не должны уходить в код VK: любой новый/правленый хук оборачивается в `HookGuard` (если он уже есть) или в локальный `try/catch` с логом и безопасным дефолтом.

## Конвенции кода
- Java (не Kotlin), без новых библиотек.
- Настройки читаются через `ru.vtosters.hooks.other.Preferences` — не создавай новые `SharedPreferences`-файлы.
- Не делай вид, что `app/src/main/AndroidManifest.xml` и `app/src/main/res/**` попадают в APK: **они не попадают** (APK собирает apktool из `smali/`).
- В горячих путях (привязка сообщения, разбор ленты, построение меню) запрещены: дисковый ввод-вывод, сеть, `Thread.sleep`, обращение к SharedPreferences на каждый элемент.
- Логирование — с тегом класса; без персональных данных, токенов и URL с `access_token`.

## Формат отчёта после шага
```
Задача: <ID и название>
Изменено: <файлы>
Почему: <причина, ссылка на file:line>
Проверка: <команда> → <результат>
Риск: <низкий/средний/высокий> + что может сломаться
Дальше: <следующий шаг или "нужно решение">
```

## Режим «внедрение фич» (когда работа идёт по GENERAL PROMPT)

- Источник задач — `FEATURES.md` в корне. Берём **одну** задачу за сессию, по приоритету и
  зависимостям; после работы обновляем статус в таблице.
- **Интерфейс переделывать нельзя, но небольшие ВРЕМЕННЫЕ вставки — можно и нужно**, иначе новые
  функции нечем проверить. Разрешено: пункт в существующем меню/тулбаре; кнопка или иконка,
  добавленная программно в существующую вьюху (без XML); строка в существующем списке на
  существующем адаптере; существующий диалог/тост/уведомление.
  Запрещено: менять существующие layout, темы, цвета, типографику; переделывать навигацию;
  «полировать» внешний вид; добавлять НОВЫЕ ресурсы в `smali/res/**` (новый ресурс = новый ID =
  правка `public.xml` + регенерация `R.java`); новые экраны «для красоты».
  Отдельный простой экран — только там, где без него функция непроверяема (MAX, Spotify, импорт
  папки): один файл, layout строится программно, за флагом.
- Каждая временная UI-вставка обязана быть: (а) за feature-флагом; (б) помечена в коде блоком
  `// TEMP-UI(<ID>): что это. Удалить после редизайна.`; (в) внесена в `FEATURES.md`, раздел
  «Временный UI» — чтобы будущий UI-агент удалил всё по списку, а не искал по всему проекту.
- Каждая новая фича закрыта флагом из `core.flags.FeatureFlags`, по умолчанию выключена.
  Читать настройки напрямую через `Preferences` в новой фиче нельзя — только через флаг.
- Новые зависимости — только с явного согласия. Разрешены уже имеющиеся: OkHttp, Gson/org.json,
  guava, streamsupport, mp3agic, AppCenter, LibVKX.
- `smali/res/values*/strings.xml` — только **текст** строк, только по задаче, где это разрешено
  владельцем. ID и `public.xml` не трогать; `rclass_regenerator` не нужен.
- MAX и другие неофициальные сервисы: в APK не должно быть ни сессий, ни токенов этих сервисов,
  ни логики их протокола. Только URL своего bridge-сервиса + токен доступа в
  EncryptedSharedPreferences, и только чтение (без массовой отправки), если задача не говорит иное.
- Массовые операции (добавление/удаление треков пачками и т.п.) — только через `RateLimiter`
  с backoff и обработкой VK Flood control (error 9).
- Капча VK (`error 14`): очередь **останавливается**, прогресс сохраняется, в отчёте — честный
  статус. Запрещено «обходить» капчу повторными попытками, пачками и фиксированными
  `Thread.sleep` в цикле импорта — это маскировка, а не решение (см. MU-10 / BUG-16).
- Сессии и токены сторонних сервисов — только `EncryptedSharedPreferences`/Keystore; в логи и
  crash-отчёты секреты не попадают.
- Новый файл, написанный с нуля, начинается с `// SPDX-License-Identifier: MIT`.
  В унаследованные/декомпилированные файлы заголовок лицензии не добавлять.
